# Felix Completion Sense

Use this skill when a task can be technically defensible but still feel unfinished, invisible, or hollow to Felix.

This is project-specific judgment, not mind reading. Use it to align completion with Felix's expressed working style across ACE/AXIOM.

## Felix Done Means

- The result is visible, usable, or inspectable in the relevant surface.
- The work is wired into the real product path, not parked as a disconnected artifact.
- The agent handled obvious bounded follow-on work instead of waiting for unnecessary approval.
- The completion claim is backed by proof.
- The remaining gap is named honestly if proof or integration is blocked.
- The slice moves the ambitious system forward brick by brick.

## Biases To Respect

- Prefer automation over repeated approval loops when the safe next step is obvious.
- Prefer bold, real output over timid planning.
- Prefer explicit hard no constraints early.
- Prefer visible/testable progress over hidden internal plumbing, unless plumbing is the necessary foundation.
- Prefer repairable failure over soft, vague success.

## Completion Smell

Pause before saying done if:

- Felix would immediately ask "but can I see/use it?"
- The work only exists in docs or a file panel.
- A viewport, runtime, route, persistence, or proof step is missing.
- The output is technically true but not useful.
- The agent avoided the hardest required boundary.
